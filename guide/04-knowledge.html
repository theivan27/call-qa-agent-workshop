Step 4

Add knowledge

Your agent doesn't need to guess what good looks like. Give it your organization's actual scorecard and compliance checklist, and watch generic feedback turn into citations.

About 15 minutes · This is the step where the agent starts being useful

1. Look at what you're about to give it

Open the three files in knowledge/:

qa_scorecard.md Five criteria totalling 100 points: Opening (15), Verification (20), Empathy and tone (20), Resolution (25), Compliance (20). Target is 80.
compliance_checklist.md Seven rules, CC-01 to CC-07, each with a severity. CC-02 (verify before discussing details) and CC-04 (no threats) are high severity.
coaching_guide.md How to phrase feedback to an agent so it's useful rather than demoralising.

These are plain markdown. That's the point — a QA manager can edit them without involving a developer. Notice that the scorecard encodes real judgement: a high-severity breach zeroes the compliance criterion outright, and Taglish is explicitly fine.

2. Attach them to the agent

In the Codespace terminal

python scripts/create_agent.py --stage 2

You'll see each file upload, then:

Agent ready: name=call-qa-reviewer version=2 stage=2 tools=1

Version 2, one tool. That tool is file search. Two things just happened: your files were uploaded to a vector store — a searchable index of their meaning, not just their words — and the agent was given the ability to search it.

Why not just paste the files into the instructions?

For three short files you could, and it would work. It stops working as the documents grow: you pay for every token on every single call, and models lose precision in very long instructions. File search retrieves only the passages that matter for the question being asked. The real win is operational, though — policy lives in files anyone can edit, separate from the agent's behaviour.

The upload logic is ensure_vector_store() in scripts/create_agent.py. It reuses an existing store rather than making a new one each run, which is why re-running the script is cheap.

3. Test the same call again

Go back to the playground in ai.azure.com. Start a new conversation — otherwise you're reading replies from the old version — and paste the same transcript from Step 3. Ask: Review this call.

This time you should get:

  • A score per criterion using the scorecard's own point values, not invented ones.
  • CC-01 flagged: no recording disclosure.
  • CC-02 flagged as high severity: the balance came before verification.
  • Credit where it's due — the payment plan offer satisfies CC-05.

That's the difference knowledge makes. Same model, same instructions, same transcript — but now the output is auditable. A QA manager can check the agent's reasoning against a document they own.

4. Change the policy without changing any code

This is the part worth remembering after today.

  1. Open knowledge/compliance_checklist.md.
  2. Add a row to the bottom of the table:
| CC-08 | Offer to send a written summary by SMS or email. | Low |
  1. Save, then re-upload:

In the Codespace terminal

python scripts/create_agent.py --stage 2 --refresh-knowledge
  1. In a new playground conversation, ask: What does CC-08 require?

It knows. You changed your compliance policy by editing a markdown file. Nobody deployed anything, nobody touched Python. That's the operating model you're selling to a QA team.

--refresh-knowledge matters

Without that flag the script reuses the existing vector store and your edit is silently ignored. If you change a file in knowledge/ and the agent seems not to notice, this is almost always why.

Checkpoint
  • create_agent.py --stage 2 printed version=2 stage=2 tools=1.
  • The agent cites CC-01 and CC-02 by number on the sample call.
  • Its scores use the scorecard's real point values.
  • It can answer a question about the CC-08 rule you invented.

If something went wrong

It still gives generic feedback with no rule numbers

Start a brand-new conversation in the playground — an existing thread can keep answering from the older agent version. Confirm the create command printed tools=1. If it printed tools=0, you ran stage 1 again.

The upload failed partway through

Clear it out and start the upload fresh:

python scripts/create_agent.py --stage 2 --refresh-knowledge

That deletes the old vector store before rebuilding it.

It cites a rule that doesn't exist

Worth seeing, because it's the failure mode to watch for in production. File search makes invention much less likely; it doesn't make it impossible. The fix is the habit: ask the agent to quote the line it's relying on, which the instructions already tell it to do, and spot-check against the source document. Step 9 turns that habit into tests.
