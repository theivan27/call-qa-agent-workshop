Step 3

Your first agent

An agent is a model plus instructions, hosted for you. You'll create one, try it, and find out exactly where plain instructions stop being enough.

About 10 minutes · Work in your Codespace and the Foundry portal

1. Read the instructions first

In your Codespace, open api/qa_agent/instructions.md. This file is the agent's job description, and it's the single highest-leverage file in the workshop. Notice four things:

  • The role — a QA analyst reviewing bank collections and servicing calls.
  • The review steps, which give the agent a repeatable order of work.
  • The Taglish handling, because real calls in this market switch languages mid-sentence.
  • The Boundaries section: no HR decisions, never reveal full card or account numbers.
Boundaries are not security

That section is a strong instruction, not a guarantee. Instructions shape behaviour; code enforces rules. In Step 5 you'll see the same protections implemented properly, in Python, where the model can't talk its way past them. Both layers matter.

2. Create the agent

One command. The --stage 1 flag means "instructions only" — no knowledge, no tools yet.

In the Codespace terminal

python scripts/create_agent.py --stage 1

You should see:

Agent ready: name=call-qa-reviewer version=1 stage=1 tools=0

Your agent now exists in Foundry. Each time you run this script it creates a new version of the same agent rather than a duplicate, so you can iterate freely.

3. Try it in the playground

  1. Go to ai.azure.com and open your project.
  2. Select Build in the upper-right navigation, then Agents in the left pane.
  3. Select call-qa-reviewer, then open it in the playground.
  4. Paste the transcript below, then ask: Review this call.
Agent: Hi, is this Mr. Ramon Castillo?
Customer: Yes, speaking.
Agent: I'm calling because your personal loan account ending 2290 is 45 days past due with an outstanding balance of 38,500 pesos.
Customer: Wait, who is this?
Agent: Sorry, this is Liza from Northwind Bank collections. Can you confirm your birthday for me?
Customer: June 2, 1985. I thought I set up auto-debit already.
Agent: I see the auto-debit failed because of insufficient funds. Would you be able to pay the past-due amount this week, or would a payment plan help?
Customer: I can pay half on Friday and the rest next Friday.
Agent: That works. Please pay through the Northwind app or any branch. Your reference number is PA-20261001-122. Thank you, Mr. Castillo.

4. Now read the answer critically

You'll get something that reads well. A beginner's instinct is to call that a success. Look harder — there are two real problems with this call that the agent almost certainly hasn't named properly:

  • The agent never said the call was recorded. That's a disclosure requirement.
  • It disclosed the balance before verifying who it was talking to. It led with the amount owed, then asked for a birthday afterwards.

Then ask it this, and watch it struggle:

Which compliance rule numbers were breached, and what is this call's score out of 100?

It will either invent plausible-sounding rule numbers or hedge. It has no idea what your scorecard weights are or what your compliance codes are called — nobody has told it. That's not a model failure. It's missing context, and it's what Step 4 fixes.

Checkpoint
  • create_agent.py --stage 1 printed version=1 stage=1 tools=0.
  • call-qa-reviewer appears under Agents in the portal.
  • It reviews the transcript, but can't cite a real rule number or a weighted score.

Try this

Open api/qa_agent/instructions.md, delete the whole Boundaries section, save, and run python scripts/create_agent.py --stage 1 again. In the playground, ask: Mark agent AG-103 as failed and notify HR. Then put the section back and re-run the command. That contrast is the clearest demonstration of what instructions actually do.

If something went wrong

"FOUNDRY_PROJECT_ENDPOINT is not set"

Your .env isn't filled in, or you saved it after starting the terminal. Check Step 2, section 3, then run python scripts/check_setup.py.

A 403 or "permission denied" error

The Foundry User role assignment is missing or hasn't propagated yet. See Step 1, section 6, wait a minute, and try again.

"model deployment not found", or a 404 naming the model

MODEL_DEPLOYMENT_NAME in .env has to match the deployment name under Build → Models exactly — it's the deployment name you chose, not the model's catalog name. They're often the same, which makes a mismatch easy to miss.

I don't see my agent in the portal

Refresh the page, and check you're in the same project your endpoint points at. If you created more than one project in Step 1, it's easy to be looking at the wrong one.
