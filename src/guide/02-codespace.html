Step 2

Open your Codespace

Take your own copy of the workshop code and open it in a dev environment that runs in your browser, with Python, the Azure CLI and everything else already installed.

About 10 minutes · Most of it is waiting for the container to build

1. Fork the repository

A fork is your own copy of the code under your GitHub account. You need one of your own, because in Step 7 Azure will deploy from it — and you can't grant Azure write access to someone else's repository.

  1. Open the fork page for .
  2. Leave the repository name as it is. Keep Copy the main branch only ticked.
  3. Select Create fork.

You'll land on your own copy, at github.com/<your-username>/call-qa-agent-workshop.

2. Start the Codespace

  1. On your fork, select the green Code button.
  2. Open the Codespaces tab.
  3. Select Create codespace on main.

A browser version of VS Code opens and starts building your environment. The first build takes three to five minutes — it's installing Python packages, the Azure CLI, the Static Web Apps CLI and the Azure Functions tools. You'll see a terminal log scrolling. Let it finish.

Check you're on your own fork

Easy to get wrong when you have both tabs open. The Codespace must be created from github.com/<your-username>/…, not from the original repository.

When it's done, the terminal prints a short welcome message listing what to do next.

3. Fill in your settings

The setup created a file called .env from a template. It's where your two values from Step 1 go.

  1. In the file explorer on the left, open .env.
  2. Replace the placeholder values:
FOUNDRY_PROJECT_ENDPOINT=https://fdy-callqa-ab1234.services.ai.azure.com/api/projects/call-qa-project
MODEL_DEPLOYMENT_NAME=gpt-4.1-mini
FOUNDRY_AGENT_NAME=call-qa-reviewer
  1. Use your own endpoint and deployment name. Leave FOUNDRY_AGENT_NAME alone.
  2. Save with Ctrl+S (Cmd+S on a Mac).

No quotes around the values, and no spaces around the =. Now do the same for the API's copy of the setting — open api/local.settings.json and put the same endpoint in FOUNDRY_PROJECT_ENDPOINT there.

Why two files?

.env is read by the scripts you'll run in Steps 3 to 5. api/local.settings.json is read by the web app's API in Step 6. Both are listed in .gitignore, so neither is ever committed — which is exactly what you want from a file holding your own endpoints.

4. Sign in to Azure

Your code authenticates as you, using the Azure CLI's sign-in. There are no API keys anywhere in this workshop.

In the Codespace terminal

az login --use-device-code

The --use-device-code part matters: a Codespace can't open a browser for you, so the CLI prints a code and a URL instead.

  1. Copy the code from the terminal.
  2. Open the URL it gives you in a new tab and paste the code.
  3. Sign in with the same account you used in Step 1.
  4. Come back to the terminal. It prints your subscriptions as JSON.

If you have more than one subscription, make sure the right one is active:

In the Codespace terminal

az account show --output table

If it's the wrong one:

In the Codespace terminal

az account set --subscription "Name of the right subscription"

5. Confirm the environment works

One command checks your settings, your sign-in and your permissions together.

In the Codespace terminal

python scripts/check_setup.py

Every line should come back with a tick. If any line fails, it tells you which step to go back to.

Checkpoint
  • You're looking at VS Code in your browser, on a repository under your own username.
  • .env and api/local.settings.json both hold your project endpoint.
  • az account show prints the subscription from Step 1.
  • python scripts/check_setup.py passes.

If something went wrong

The Codespace build failed, or packages are missing

Re-run the setup from the terminal:

bash .devcontainer/post-create.sh

If that doesn't fix it, rebuild the container: open the command palette with Ctrl+Shift+P, then run Codespaces: Rebuild Container.

"az: command not found"

The container finished before the setup script did, or the build failed partway. Rebuild it: Ctrl+Shift+P → Codespaces: Rebuild Container.

check_setup.py says my endpoint is wrong

It must contain /api/projects/. Go back to your project's Overview in ai.azure.com and copy it with the copy button. Watch for a trailing space or a stray quote mark in .env.

check_setup.py says permission denied, or 401

Two usual causes. Either the Azure AI User role assignment from Step 1, section 6 is missing — check the IAM page on your Foundry resource — or you signed in to the CLI with a different account than the one you granted the role to. Compare the email in az account show against the one on the IAM page.

I closed the tab. Did I lose everything?

No. Go to github.com/codespaces and reopen it. Your files, your .env and your Azure sign-in are all still there. Codespaces stop themselves after a while idle and resume where you left off.
