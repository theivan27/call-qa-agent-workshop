Step 1

Create the project

A resource group to hold everything, a Foundry project to host your agent, and a model for it to think with. All in the portal — no commands yet.

About 15 minutes · You'll finish with two values to copy into Step 2

1. Create a resource group

Do this first and put everything in it. In Step 10 you delete this one group and the whole workshop disappears, which is the difference between a workshop that cost you cents and one that quietly bills you for months.

  1. Go to portal.azure.com.
  2. In the top search box, type Resource groups and select it.
  3. Select + Create.
  4. Fill in the form:
SubscriptionYours. If there are several, pick the one you're happy to spend from.
Resource grouprg-call-qa-workshop
RegionSomewhere near you, for example Southeast Asia. This only sets where the group's metadata lives.
  1. Select Review + create, then Create.

2. Set a budget alert

Two minutes now buys you peace of mind for the rest of the month.

  1. Search for Cost Management and open it.
  2. Select Budgets → + Add.
  3. Scope it to your subscription. Name it workshop-budget, and set the amount to something small but real — 5 in your currency is plenty.
  4. Add an alert condition at 80% of budget and enter your email address.
  5. Select Create.
What this does and doesn't do

A budget alert emails you. It does not cap spending or switch anything off. It's a smoke detector, not a sprinkler.

3. Create the Foundry project

A project is your workspace for agents, models and knowledge. Creating one also creates the underlying Foundry resource — the billable Azure thing the project sits on.

  1. Go to the Foundry portal at ai.azure.com and sign in with the same account.
  2. Select + Create new, then choose to create a Foundry project.
  3. Before you confirm, open Advanced options. This matters — it's where you point the new resource at the group you just made:
Project namecall-qa-project
Foundry resourceA new one. The name has to be globally unique, so add something of your own: fdy-callqa-ab1234.
SubscriptionThe same one as your resource group.
Resource grouprg-call-qa-workshop
RegionSee the note below.
  1. Select Create and wait. This takes a minute or two.
Choosing a region

Models aren't available everywhere, and the nearest region isn't always the best choice. If you can't find gpt-4.1-mini in the next section, the region is usually why — East US 2 and Sweden Central tend to carry the widest selection. Latency doesn't matter for a workshop, so favour availability over proximity.

4. Deploy a model

A model deployment is your own named endpoint for a model. Your agent will refer to it by that name.

  1. In your project, open Models + endpoints in the left navigation.
  2. Select + Deploy model → Deploy base model.
  3. Search for gpt-4.1-mini and select it, then Confirm.
  4. Leave the Deployment name as gpt-4.1-mini. If you change it, write down what you chose — you'll need it in Step 2.
  5. Select Deploy.

Any small, cheap chat model works here. If gpt-4.1-mini isn't offered, pick another mini or small model and use its deployment name throughout.

5. Copy your two settings

Step 2 needs exactly two values. Collect them now and paste them somewhere temporary.

The project endpoint. On your project's Overview page in the Foundry portal, find the endpoint and copy it. It looks like this: 

https://fdy-callqa-ab1234.services.ai.azure.com/api/projects/call-qa-project
Get this one exactly right

The Overview page may show several URLs. You want the one containing /api/projects/. A plain https://<name>.services.ai.azure.com with no project path is the resource endpoint, not the project endpoint, and it will fail later with a confusing error. Copy it with the button rather than retyping it.

The model deployment name. Whatever you left in the box in section 4 — gpt-4.1-mini unless you changed it.

6. Give yourself permission to use it

This catches almost everyone. Creating a resource makes you its Owner, which lets you manage it — but managing and using are different permissions in Azure. Calling the agent API needs the Azure AI User role, and Owner doesn't include it.

  1. Back in portal.azure.com, open your resource group rg-call-qa-workshop.
  2. Select the Foundry resource you created (fdy-callqa-ab1234).
  3. Select Access control (IAM) in the left navigation.
  4. Select + Add → Add role assignment.
  5. In the Role list, search for Azure AI User and select it. Then Next.
  6. Leave User, group, or service principal selected and choose + Select members. Find yourself, select your account, then Select.
  7. Select Review + assign.

Role assignments can take a minute or two to take effect. If Step 3 fails on permissions, wait a moment and try again.

Checkpoint

You should now have:

  • A resource group rg-call-qa-workshop containing your Foundry resource.
  • A model deployment showing Succeeded under Models + endpoints.
  • Your project endpoint and deployment name saved somewhere you can paste from.
  • Your own account listed with Azure AI User on the Foundry resource's IAM page.

If something went wrong

I can't find gpt-4.1-mini in the catalog

Your region doesn't serve it. Either pick a different small chat model that is offered, or create a second project in East US 2 or Sweden Central and use that one. If you create another project, use its endpoint in Step 2 — and put it in the same resource group so Step 10 still catches it.

"You do not have permission to create a role assignment"

You're a Contributor, not an Owner, on that scope. Contributors can create resources but not grant access. Ask an administrator to assign you Azure AI User on the Foundry resource, or run the workshop on a personal subscription where you're Owner.

The deployment says it failed, or there's no quota

New subscriptions sometimes start with no quota for a given model in a given region. Open Management centre → Quota in the Foundry portal to see what you have. The fastest fix is to deploy in a different region or pick a different model rather than waiting on a quota increase.

I lost the project endpoint

It's always on the project's Overview page in ai.azure.com. You can also rebuild it by hand: https://<foundry-resource-name>.services.ai.azure.com/api/projects/<project-name>.
