Step 6

Run the web app

A terminal is a hard sell to a QA manager. Put the same agent behind a web page that shows every tool call as it happens.

About 15 minutes · Everything runs inside your Codespace

1. What you're starting

Two pieces, one command:

  • src/ — the front end. Plain HTML, CSS and JavaScript, no framework. (This guide is in there too, at src/guide/.)
  • api/ — two Azure Functions. GET /api/calls lists the sample calls; POST /api/chat runs the same tool loop the CLI used.

The front end never talks to Foundry. It talks to your API, and the API talks to Foundry. Keep that shape in your own projects — it's what stops credentials ending up in a browser.

2. Check the API's settings

You filled this in during Step 2, but it's the single most common reason this step fails, so confirm it now. Open api/local.settings.json and check FOUNDRY_PROJECT_ENDPOINT holds your real endpoint.

Two files, deliberately

The scripts read .env; the Functions host reads api/local.settings.json and ignores .env entirely. That's a Functions convention, not something this project invented. Locally the API signs in as you via az login — in Step 8 you'll give the deployed version its own identity.

3. Start it

In the Codespace terminal

swa start src --api-location api

The Static Web Apps CLI starts the front end and the Functions host together and puts them on one address, which is how they'll be served in Azure. The first start takes thirty seconds or so while the Python worker warms up. Wait for a line like: 

Azure Static Web Apps emulator started at http://localhost:4280

4. Open it

Codespaces notices port 4280 and shows a notification with Open in Browser. Select it. If you miss the notification, open the Ports tab next to the terminal and select the globe icon on port 4280.

You'll get a *.app.github.dev URL rather than localhost — that's Codespaces forwarding the port out of the container. The URL is private to your GitHub account by default.

5. Review a call

  1. Pick a call from Calls to review on the left.
  2. Send the suggested request.
  3. Watch What the agent did on the right.

That third panel is the point of this app. Every transcript read, knowledge search, saved score and compliance flag appears in order, as it happens. Select Show details on any entry to see the exact arguments the agent passed and what your code returned.

Show that panel to anyone sceptical about letting an AI near their QA process. "It gave call C-5533 a 44" invites an argument. "It gave it a 44, here are the four rules it cites and the lines it quoted" is a conversation about the call instead.

Worth trying in the UI

  • C-5533 — the worst call in the set. Threats and a payment to a personal e-wallet: CC-04 and CC-06, both high severity.
  • C-5531 — watch the card number come back masked in the tool result.
  • Mark agent AG-103 as failed and notify HR. — refused here exactly as it was in the CLI.
  • Start new review — clears the conversation so the agent isn't carrying context from the last call.
Checkpoint
  • The app loads in your browser and the calls list is populated.
  • Sending a request produces a scored review.
  • What the agent did lists tool calls with arguments and results.
  • Visiting /guide/ on the same URL shows this guide.

If something went wrong

"Couldn't load calls"

The front end is up but the API isn't answering. Look at the terminal for Functions host errors — they appear below the emulator banner. Most often the Python worker failed to start because a package is missing: 

pip install -r api/requirements.txt

Then stop swa start with Ctrl+C and start it again.

"FOUNDRY_PROJECT_ENDPOINT is not set"

The API is reading api/local.settings.json, not .env. Fill in the endpoint there, then restart swa start — it only reads settings at startup.

"Agent not found"

Run python scripts/create_agent.py --stage 3, and make sure FOUNDRY_AGENT_NAME is the same in .env and api/local.settings.json. If you renamed the agent in one file only, this is the error you get.

Authentication errors in the terminal

Your CLI sign-in has lapsed. Run az login --use-device-code again, then restart swa start.

"swa: command not found"

Re-run the environment setup, which installs it:

bash .devcontainer/post-create.sh
The request times out or takes forever

Reviewing several calls at once means many model calls in sequence. Start with one call. Note the limit for later: once deployed, the built-in API cuts requests off at about 45 seconds, which Step 7 comes back to.
