Step 10

Delete everything

The workshop cost you cents. Forgetting this page is what turns that into a monthly bill. Five minutes, in this order.

About 10 minutes · Do it today, not next week

Want to keep the app running for a demo?

You can — the ongoing cost is small, mostly vector storage. But set a calendar reminder to come back and do this, and make sure you finished the sign-in step in Step 8 so a public URL isn't spending your model budget. Everything below will still be here when you need it.

1. Save anything you want to keep

Deleting the Azure resources doesn't touch your GitHub fork, so your code, your sixth tool and your CC-08 rule all survive. What won't survive: your agent and its versions, your vector store, and your deployed site's URL.

If you changed anything in your Codespace that you haven't pushed, push it now — this is your last chance before you delete the Codespace.

In the Codespace terminal

git add .
git commit -m "Workshop changes"
git push

2. Delete the resource group

This is the big one. It removes the Foundry resource, your project, the agent, the vector store and the Static Web App in a single action — which is exactly why Step 1 had you put everything in one group.

  1. Go to portal.azure.com and open Resource groups.
  2. Select rg-call-qa-workshop.
  3. Before deleting, glance down the list of resources. Anything here you didn't expect? If you created a project in a second region in Step 1, it may be in a different group — note it and come back for it.
  4. Select Delete resource group at the top.
  5. Type the group's name to confirm, then Delete.

It takes a few minutes. You can close the tab; it carries on.

Or, if you'd rather do it from the terminal:

In the Codespace terminal

az group delete --name rg-call-qa-workshop --yes --no-wait
This cannot be undone

Deleting a resource group permanently destroys everything inside it. Read the resource list before you confirm, and be certain the name is rg-call-qa-workshop and not a group holding something you care about.

3. Delete the service principal

This one lives in Entra ID, not in your resource group, so the delete above left it behind. It costs nothing, but it's a credential that can still authenticate — leaving unused identities lying around is how real breaches start.

In the Codespace terminal

az ad sp delete --id 11111111-2222-3333-4444-555555555555

Use your own appId. Lost it? Find it by name:

In the Codespace terminal

az ad sp list --display-name call-qa-reviewer-web --query "[].appId" --output tsv

Skipped Step 8? Then you never created one, and there's nothing to delete.

4. Check nothing else is running

Resources sometimes end up outside the group you intended — particularly if you created a second Foundry project while hunting for model availability. Check:

In the Codespace terminal

az resource list --output table

Anything left from today, delete it. An empty table, or only resources you recognise from before the workshop, means you're clear.

5. Stop or delete your Codespace

Codespaces bill for the time they run and the storage they use, against your GitHub allowance.

  1. Go to github.com/codespaces.
  2. Find the one for your fork.
  3. Use the … menu: Stop codespace keeps your files and stops the compute charge. Delete codespace removes the storage charge too.

Delete it unless you plan to come back within a few days. Everything you pushed is on GitHub, and a new Codespace rebuilds from your fork in minutes — you'd just need to redo .env and az login.

6. Tidy up GitHub

Optional, but worth doing while it's fresh:

  • The deployment token secret Azure created is now useless. Remove it under Settings → Secrets and variables → Actions on your fork.
  • The generated azure-static-web-apps-*.yml workflow will fail on every future push, pointing at a web app that no longer exists. Delete the file, or leave it — a red tick on a workshop fork harms nothing.
  • Revoke Azure's access to your GitHub account if you'd rather not leave it in place: Settings → Applications → Authorized OAuth Apps.

7. Confirm with your own eyes

Costs take up to a day to settle, so don't expect zero immediately. Check in a couple of days: in the portal, open Cost Management → Cost analysis, set the range to this month and group by resource. Everything from today should be flat-lining.

Leave the budget alert from Step 1 in place even now. It costs nothing and it's the thing that tells you if you missed something.

Final checkpoint
  • rg-call-qa-workshop no longer appears under Resource groups.
  • The service principal is deleted.
  • az resource list shows nothing from today.
  • Your Codespace is stopped or deleted.
  • Your fork still has your code.

You're done

Today you built an agent that reads a call, judges it against your rules and files the result. Along the way:

  • Instructions define the job — and are the cheapest thing to iterate on.
  • Knowledge turns generic feedback into citations, and lets policy live in files a manager owns.
  • Tools are the real boundary of what an agent can do. The model proposes; your code decides.
  • Guardrails in code beat guardrails in prompts. You saw one survive a deletion and the other vanish.
  • Evaluation is what makes a demo into something you'd ship.

Your fork is yours to keep. The most useful next move is to swap in your own scorecard and checklist from your actual QA process, re-run the knowledge step, and see how it does on a transcript you already know the right answer to.

If something went wrong

The resource group won't delete

Usually a lock or a dependency. Open the group's Locks page and remove any lock, then retry. If one resource is stubborn, delete that resource on its own first, then the group.

I deleted the group but still see charges

Billing lags by up to 24 hours, and you'll still see charges for the hours before you deleted. If new charges are still appearing after two days, something survived — run az resource list --output table and check other resource groups.

"az ad sp delete" says insufficient privileges

You could create it but not remove it, which happens on managed tenants. Ask an administrator to delete the call-qa-reviewer-web app registration. It can't reach anything useful now that the Foundry resource is gone, but it should still be cleaned up.

I deleted the resource group but wanted to keep the app

Nothing is lost that matters. Your fork still has every file. Redo Step 1 and Step 7 — second time round it's about twenty minutes. The site URL will be different.
